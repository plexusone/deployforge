## [v0.1.0] - 2026-11-23

### Highlights

- The first release: deploy Go apps to your own Linux hosts with release archives, systemd and Caddy, a ledger, the edge, databases and credentials, from one fleet document

### Added

- The fleet document: hosts (an address, or one from a Pulumi output), a port range, apps with named stacks, per-stack databases, limits and status, app labels, the database server and the credential registry, validated with every problem reported, and its JSON Schema
- Releases from a clean, tagged, pushed commit, with the revision and checksum; local builds from local commits with upstream Go modules through a generated go.work and npm packages packed with pnpm, every input named in the archive and the ledger
- Deploys over SSH with no agent on the host: unpack, install with backup, validate, migrate, an atomic switch, readiness on every host name, restore on failure, pruning; a deploy lock and an on-host audit log; deploy ship, release, rollback, unlock, status and unpushed
- A ledger of every deploy and rollback per stack, with record, show, current and import from another tool's ledger
- Hooks around packaging, deploy and rollback, and on failure, with no secret value in their environment
- The host: systemd units with a hardening sandbox and limits, an idempotent host-setup script, a Caddyfile per host validated on the host before it is reloaded, and next-port
- The edge: zones checked against their name servers, the security baseline through Cloudflare's API as plan, apply and verify, origin certificates made on the host and signed by Cloudflare, and a minimum TLS check from outside
- Databases: owner and app roles with connection limits and SCRAM verifiers, their passwords in the parameter store; snapshots before a primary stack's deploy and on demand; copies between servers with row counts compared, and promotion of the new server's parameters
- Credentials: the credential registry the fleet names, with systemspec-credential's commands and credforge's check, generate, install, review and setup; an HTML page per stack; a check before ship that every secret under the stack's prefix exists
- Access: an IAM policy and an operators' group per stack's parameter-store prefix, as plan, apply and verify
- Every capability as a Go package, and the Cobra command tree mountable under a host tool's command
