## [v0.2.0] - 2026-11-25

### Highlights

- deploy ship refuses a release script that is not executable in the commit it packages, and --dry-run packages and checks a release without deploying it
- A failed deploy names the step it stopped at, and ship, release, rollback and status can write one JSON report
- iam apply needs --confirm, and iam policy prints a stack's policy for review

### Added

- A failed release or rollback carries the step it stopped at (unpack, install, validate, the self-check's stages, migrate, switch or health), whether the running release was kept or restored, and whether the migration stays applied ([`adfd039`](https://github.com/plexusone/deployforge/commit/adfd039))
- --format json on deploy ship, release, rollback and status: one JSON report on standard output with the phase that failed, the host's failure, the ledger entry and ship's snapshot; progress goes to standard error ([`459f52f`](https://github.com/plexusone/deployforge/commit/459f52f))
- deploy ship checks, in the commit it packages, that the release script is executable (git mode 100755) and stops with the git update-index --chmod=+x fix when it is not; a shell script beside it that is not executable is reported as a warning ([`ee4c7d6`](https://github.com/plexusone/deployforge/commit/ee4c7d6))
- deploy ship --dry-run packages and checks the release, then stops: nothing is snapshotted, deployed or recorded ([`d91e2a4`](https://github.com/plexusone/deployforge/commit/d91e2a4))
- cli.Options.ReleaseEnv and ship.Options.Env give release scripts extra environment, for scripts at older tags that read other names; release package accepts --sites as an older name of --fleet ([`d91e2a4`](https://github.com/plexusone/deployforge/commit/d91e2a4))
- iam policy prints one stack's policy document for review, with --account, reading no AWS account ([`6c96988`](https://github.com/plexusone/deployforge/commit/6c96988))
- cloudflare-ips refreshes the committed Cloudflare ranges from the published lists, and --check fails when this build's ranges are out of date ([`8f4d9c0`](https://github.com/plexusone/deployforge/commit/8f4d9c0))

### Changed

- iam apply needs --confirm: without it, it shows the plan, changes nothing and says to run again with --confirm ([`6c96988`](https://github.com/plexusone/deployforge/commit/6c96988))
- For an app behind cloudflare, validate refuses a host name more than one label under its domain, which the zone's certificates do not cover ([`bb8fa9a`](https://github.com/plexusone/deployforge/commit/bb8fa9a))

### Dependencies

- _3 dependency updates_

### Documentation

- Migrations a rollback survives, and the JSON reports ([`7a42a72`](https://github.com/plexusone/deployforge/commit/7a42a72))

## [v0.1.0] - 2026-11-23

### Highlights

- The first release: deploy Go apps to your own Linux hosts with release archives, systemd and Caddy, a ledger, the edge, databases and credentials, from one fleet document

### Added

- The fleet document: hosts (an address, or one from a Pulumi output), a port range, apps with named stacks, per-stack databases, limits and status, app labels, the database server and the credential registry, validated with every problem reported, and its JSON Schema
- Releases from a clean, tagged, pushed commit, with the revision and checksum; local builds from local commits with upstream Go modules through a generated go.work and npm packages packed with pnpm, every input named in the archive and the ledger
- Deploys over SSH with no agent on the host: unpack, install with backup, validate, migrate, an atomic switch, readiness on every host name, restore on failure, pruning; a deploy lock and an on-host audit log; deploy ship, release, rollback, unlock, status and unpushed
- A ledger of every deploy and rollback per stack, with record, show, current and import from another tool's ledger
- Hooks around packaging, deploy and rollback, and on failure, with no secret value in their environment
- The host: systemd units with a hardening sandbox and limits, an idempotent host-setup script, a Caddyfile per host validated on the host before it is reloaded, and next-port
- The edge: zones checked against their name servers, the security baseline through Cloudflare's API as plan, apply and verify, origin certificates made on the host and signed by Cloudflare, and a minimum TLS check from outside
- Databases: owner and app roles with connection limits and SCRAM verifiers, their passwords in the parameter store; snapshots before a primary stack's deploy and on demand; copies between servers with row counts compared, and promotion of the new server's parameters
- Credentials: the credential registry the fleet names, with systemspec-credential's commands and credforge's check, generate, install, review and setup; an HTML page per stack; a check before ship that every secret under the stack's prefix exists
- Access: an IAM policy and an operators' group per stack's parameter-store prefix, as plan, apply and verify
- Every capability as a Go package, and the Cobra command tree mountable under a host tool's command

### Documentation

- A MkDocs site with user guides, the release notes and the design documents
