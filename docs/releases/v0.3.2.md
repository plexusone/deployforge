# Release Notes v0.3.2

Released: 2026-11-26

## Highlights

- **The unit is checked before each ship.** A change to a stack's
  `limits`, such as its memory, changes the systemd unit `host setup`
  installs, and a deploy only restarts the service under the unit already
  on the host. Each stack's deploy runbook now checks that unit first, so
  the new one is installed before the deploy that applies it.

## Added

- `host setup <app> <stack> --check` reads the stack's unit installed on
  its host and compares it with the one the fleet document gives, comments
  and blank lines aside. It exits non-zero, naming the first line that
  differs and the fix, when they do not match or the host has no unit
  yet. It changes nothing.
- The deploy runbook's first step, the operator's shell, runs
  `host setup --check`. The runbook's troubleshooting names
  `host setup --apply` for a unit that is out of date or missing.

## Documentation

- The hosts and deploying guides describe `host setup --check`.

## Upgrading

No change is needed. Regenerate deploy runbook pages to show the new check.
