# Release Notes v0.3.0

Released: 2026-11-26

## Highlights

What a tool built around deployforge kept writing for itself is now
deployforge's: loading a data-only dump into a stack's database, a
per-stack credential check that records what it finds, a check of a
host's firewall, a recurring deploy runbook for each live stack, the
pieces a tool's own runbooks keep needing, and the fleet's pages.

## Added

- **`db import`.** `db import <app> <stack> <database> --file <dump>`
  loads a plain data-only dump (`pg_dump --data-only`) as the database's
  owner, with `psql` on the database server's via host, in one
  transaction. Tables whose row-level security is forced on their owner
  have `FORCE` lifted for the load and put back. It prints each table's
  row count, and without `--confirm` the transaction is rolled back.
  `--replace OLD=NEW` replaces text first. The dump may hold no `psql`
  meta-command outside COPY data. `Options.ImportHook` lets a tool add
  flags and replacements of its own, such as an ID it looks up in the
  target database.
- **`credentials preflight`.** `credentials preflight <app> <stack>`
  compares the stack's secret prefix with the registry, as the check in
  `deploy ship` does, and shows all of it: each credential present, with
  its store's date and whether the event log records it; each missing;
  and each name no credential lists, with a database move's `next/` and
  `previous/` values counted. `--record` records present credentials the
  log lacks as created, `--include-planned` compares planned ones too,
  and `--require-recorded` fails while any is unrecorded.
  `preflight.Inspect` is the package form.
- **`host ports`.** `host ports <host> --admin-cidr <cidr>...` reads a
  Lightsail instance's port states and fails unless HTTPS is open exactly
  to Cloudflare's IPv4 ranges (with `--ipv6`, its IPv6 ranges too), SSH
  only to the admin addresses, and no other port is open. It changes
  nothing. Run it after any change to the firewall: a tool that replaces
  the rules new-first, then deletes the old set, can close the ports it
  just opened. A host names its instance with `lightsailName`.
- **Deploy runbooks.** `deploy runbook --app <app> --stack <stack>` is a
  live stack's recurring deploy runbook, one run per deploy: the
  operator's shell, the stack's secrets, a dry run, the ship, and the
  deploy recorded, with every host name's readiness checked. It has
  systemspec-runbook's commands (`list`, `prepare`, `run`, `restart`,
  `state`, `doc` and more) and `export`. Each stack's event log is
  `deployments/runbooks/<app>-<stack>.events.json`.
- **`runbookkit`.** Pieces for a tool's own runbooks: `RemoteQuote` and
  `SSH` quote arguments for the remote shell, which ssh joins with
  spaces; `InstallFromConsole`; `PermissionList`, sorted part by part;
  `AddNeeds`, which names each step's inputs from its commands;
  `AgentKey` and `Token` inputs; and `Fixes` for SSH timeouts and refused
  keys, a release script without its executable bit, a missing value,
  missing credentials, and missing tokens.
- **Fleet pages.** `fleet inventory` writes the fleet's inventory page,
  and `fleet format` the fleet document's format reference, from the Go
  types the schema is generated from.
- **Options.** `ImportHook`, `HostPorts`, `RunbookTool` and `RunbookDir`.

## Changed

- **Schema.** The fleet document's schema adds `hosts[].lightsailName`.
  Existing documents are unchanged.

## Documentation

- The README, and the databases, credentials, hosts, deploying,
  fleet-document and embedding guides, describe the new commands,
  packages and options.

## Upgrading

No change is needed. To check a host's firewall, give the host its
`lightsailName`. A tool that kept its own deploy runbooks can move them
to `deploy runbook`; their event logs move to `deployments/runbooks/`
unless the tool sets `Options.RunbookDir`.
