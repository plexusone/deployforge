# Release Notes v0.2.0

Released: 2026-11-25

## Highlights

A deploy fails earlier and says more. `deploy ship` refuses a release
script that is not executable in the commit it packages, before anything
runs, and `--dry-run` packages and checks a release without deploying it.
A failed deploy names the step it stopped at, and the deploy commands can
write one JSON report. `iam apply` now needs `--confirm`.

## Added

- **The step a deploy stopped at.** A failed release or rollback carries
  the step it stopped at (unpack, install, validate, the self-check's
  stages, migrate, switch or health), whether the running release was kept
  or restored, whether a first release left the service stopped, and
  whether the migration completed and stays applied.
- **JSON reports.** `--format json` on `deploy ship`, `release`,
  `rollback` and `status` writes one JSON report on standard output: whether
  it succeeded, the phase that failed, the host's failure, the ledger entry
  and ship's database snapshot. Progress goes to standard error, and the exit
  status is unchanged.
- **An executable release script.** `deploy ship` reads the mode git
  recorded for the release script in the commit it packages, and stops
  unless it is `100755`, with the fix:

  ```bash
  git update-index --chmod=+x ops/host/release.sh
  ```

  A script committed without its executable bit otherwise fails with
  "permission denied" in every checkout of that commit, whatever the mode
  in yours. A shell script beside it that is not executable is reported as
  a warning, since the release script may run it.
- **Dry runs.** `deploy ship --dry-run` packages and checks the release,
  then stops: nothing is snapshotted, deployed or recorded.
- **Release-script environment.** `cli.Options.ReleaseEnv` and
  `ship.Options.Env` give a release script extra environment, for scripts
  at older tags that read other names for the binary and the fleet
  document. `release package` accepts `--sites` as an older name of
  `--fleet`.
- **`iam policy <app> <stack>`** prints the stack's policy document for
  review, with `--region` and `--account`, and reads no AWS account.
- **`cloudflare-ips`** writes the IPv4 and IPv6 ranges Cloudflare publishes
  to `deploy/cfranges`, for review and a release; `--check` writes nothing
  and fails when the ranges this build carries are out of date.

## Changed

- **`iam apply` needs `--confirm`.** Without it, it shows the plan,
  changes nothing, and says to run again with `--confirm`.
- **Host names behind Cloudflare.** For an app whose edge is `cloudflare`,
  `validate` refuses a host name more than one label under its domain, such
  as `a.b.example.com`: the zone's edge and origin certificates cover only
  the zone and `*.zone`, so it would fail TLS.

## Dependencies

- Requires `github.com/plexusone/systemspec-runbook` v0.4.1.
- Requires `github.com/plexusone/credforge` v0.11.1: the deploy preflight
  never counts a credential needed only during a rotation, such as a
  verification secret, as missing.
- Indirect dependency updates.

## Upgrading

- Add `--confirm` to every `iam apply` in scripts and runbooks.
- A fleet document with a host name two labels under a Cloudflare zone no
  longer validates. Move the host one label under the zone, or set the
  app's `edge` to empty if it is not behind Cloudflare.
- If a deploy now stops on the release script's mode, run the
  `git update-index --chmod=+x` fix it gives, commit, and tag again.
