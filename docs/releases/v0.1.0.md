# Release Notes v0.1.0

Released: 2026-11-23

## Highlights

The first release. deployforge deploys Go apps to Linux hosts you already
have, from one fleet document: a release archive per deploy, systemd
behind Caddy, secrets from a parameter store, and a ledger of every
release. Around the deploy it prepares the hosts, the edge, the databases
and the credentials.

## Added

- **The fleet document.** Hosts (an address, or one read from a Pulumi
  output), a port range, apps with named stacks, each stack's databases,
  limits and status, app labels, the database server and the credential
  registry. Validation reports every problem at once, and `schema`
  prints its JSON Schema.
- **Releases.** A reproducible archive from a clean, tagged, pushed
  commit, with its revision and checksum. A local build takes local
  commits, with upstream Go modules through a generated `go.work` and npm
  packages packed with pnpm; every input is named in the archive and the
  ledger.
- **Deploys.** Over SSH, with no agent on the host: unpack, install with
  a backup, `validate`, `migrate`, an atomic switch, readiness on every
  host name, a restore on any failure, and pruning. A deploy lock and an
  audit log on the host. `deploy ship`, `release`, `rollback`, `unlock`,
  `status` and `unpushed`.
- **The ledger.** Every deploy and rollback per stack, in your
  repository, with `record`, `show`, `current`, and `import` from another
  tool's ledger.
- **Hooks** around packaging, deploy and rollback, and on failure, with
  no secret value in their environment.
- **Hosts.** systemd units with a hardening sandbox and limits, an
  idempotent host-setup script, a Caddyfile per host validated on the
  host before it is reloaded, and `next-port`.
- **The edge.** DNS zones checked against their name servers, a security
  baseline applied through Cloudflare's API (`plan`, `apply`, `verify`),
  origin certificates made on the host and signed by Cloudflare, and
  `zones tls`, a minimum TLS check from outside.
- **Databases.** Owner and app roles per database with connection limits
  and SCRAM verifiers, their passwords in the parameter store; snapshots
  before a primary stack's deploy and on demand; `db copy` between
  servers with row counts compared, and promotion of the new server's
  parameters.
- **Credentials.** The credential registry the fleet names, with
  systemspec-credential's commands and credforge's `check`, `generate`,
  `install`, `review` and `setup`; an HTML page per stack; and a check
  before `ship` packages anything that every secret under the stack's
  prefix exists.
- **Access.** An IAM policy and an operators' group for each stack's
  parameter-store prefix (`iam plan`, `apply`, `verify`).
- **Embedding.** Every capability is a Go package, and the Cobra command
  tree mounts under a host tool's own command.
- **Documentation.** A MkDocs site with user guides, these notes and the
  design documents.
